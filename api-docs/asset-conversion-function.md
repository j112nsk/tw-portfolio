# Техническое описание функции «Мгновенная конвертация активов»
## 1. Назначение функции
Функция позволяет пользователю быстро обменять один цифровой актив на другой (например, BTC → USDT) по фиксированной котировке, предоставленной системой. Пользователь не взаимодействует со стаканом и не выставляет ордера - он принимает предложенную цену или отказывается.

**Пользовательская ценность:**
- Мгновенная конвертация без необходимости разбираться в торговых механизмах;
- Возможность мгновенно зафиксировать стоимость актива;
- Отсутствие рыночного риска во время TTL котировки.

**Бизнес‑ограничения биржи:**
- Котировка должна быть валидна ограниченное время (TTL);
- Биржа должна иметь возможность отклонить или отменить конвертацию в случае изменения рыночных условий или недостатка ликвидности;
- Комиссия должна быть видна пользователю и применена корректно.

## 2. Исходные допущения
### 2.1 В системе уже существуют допущения:
- Балансы пользователя по каждому активу;
- Справочник активов - включает в себя точность (количество знаков после запятой) и минимальная сумма ввода/вывода/конвертации;
- Торговая пара - определяет допустимое направление конвертации между активами, а также минимальный объём операции;
- Комиссия на конвертацию (фиксированная или процентная);
- Котировка с TTL - цена действительна ограниченное время.

### 2.2 Дополнительные допущения:
- Комиссия удерживается в активе, который пользователь получает;
- Котировка включает цену и рассчитанную сумму получения;
- Операция конвертации является атомарной: либо выполняется полностью, либо не выполняется вовсе;
- После истечения TTL котировка становится недействительной и должна быть запрошена заново.

## 3. Пользовательский сценарий

### 3.1 Основной сценарий (Happy Path):
| № | Действие                                                                         |
|---|----------------------------------------------------------------------------------|
| 1 | Пользователь выбирает исходный актив, целевой актив и вводит сумму конвертации   |
| 2 | Система проверяет корректность ввода и доступность торговой пары                 |
| 3 | Система рассчитывает котировку и отображает: курс, итоговую сумму, комиссию, TTL |
| 4 | Пользователь подтверждает операцию в пределах TTL                                |
| 5 | Система повторно проверяет баланс и актуальность котировки                       |
| 6 | Система выполняет конвертацию и обновляет балансы                                |
| 7 | Пользователь получает подтверждение успешной операции                            |

### 3.2 Альтернативные сценарии и ошибки:
|     Ошибка / Условие                     |     Описание поведения системы                                                |     Точка возникновения                   |
|------------------------------------------|-------------------------------------------------------------------------------|-------------------------------------------|
|     Недостаточно средств                 |     Операция отклоняется                                                      |     Перед шагом 6 (повторная проверка)    |
|     Истёк TTL                            |     Сервер возвращает ошибку, клиент предлагает запросить новую котировку     |     На шаге 4–5                           |
|     Торговая пара недоступна             |     Система не позволяет запросить котировку и показывает сообщение           |     На шаге 2                             |
|     Сумма ниже минимальной               |     Ввод отклонён, котировка не формируется                                   |     На шаге 1–2                           |
|     Техническая ошибка при исполнении    |     Операция не выполняется, балансы не изменяются                            |     На шаге 6                             |

## 4. Доменная модель
|     №    |     Сущность                   |     Назначение                                                                                                                       |     Ключевые поля                                                                                                                  |

|     1    |     Пользовательский баланс    |     Хранит информацию о доступных средствах пользователя по каждому   активу и используется для проверки возможности конвертации.    |     ИД пользователя,     код актива,     доступная сумма                                                                           |
|     2    |     Актив                      |     Описывает криптоактив и его параметры, необходимые для корректных   расчётов.                                                    |     код актива, точность, минимальное кол-во                                                                               |
|     3    |     Торговая пара              |     Определяет допустимое направление конвертации между двумя активами.                                                              |     исходный актив, целевой актив                                                                                              |
|     4    |     Котировка конвертации      |     Фиксирует условия обмена, предлагаемые пользователю на ограниченное   время.                                                     |     исходный актив,     целевой актив,     цена целевого актива,     общая сумма,     время действия котировки                     |
|     5    |     Операция конвертации       |     Отражает факт попытки и результат выполнения конвертации.                                                                        |     ИД операции, ИД пользователя, исходный актив, целевой актив, сумма до, сумма после,     статус операции    |

## 5. Алгоритм расчёта
1.	Пользователь указывает сумму исходного актива.
2.	Система проверяет доступность торговой пары и соответствие минимальному значению и точности исходного актива.
3.	Рассчитывается сумма целевого актива без учёта комиссии.
4.	Рассчитывается комиссия.
5.	Итоговая сумма к получению.
6.	Итоговая сумма округляется в соответствии с точностью целевого актива.
7.	Система формирует котировку и фиксирует её на время TTL.

**Проверки перед выполнением операции:**
- Котировка не истекла;
- Баланс пользователя по исходному активу достаточен для списания;
- Итоговая сумма соответствует минимальному значению целевого актива;
- Торговая пара активна на момент исполнения.

## 6. API-интерфейс
### 6.1 Получение котировки
**Назначение:** Запрос котировки.

**Метод и URL:** POST/quote

**Входные параметры:**
- код исходного актива
- код целевого актива
- сумма исходного актива

**Выходные данные:**
- идентификатор котировки
- цена целевого актива
- курс конвертации
- сумма к получению после комиссии и округления
- время окончания действия котировки

**Основные ошибки:**
- 404 Not Found - торговая пара недоступна
- 400 Bad Request - нарушены ограничения по минимальной сумме или точности
- 400 Bad Request - недостаточно средств для формирования котировки
- 503 Service Unavailable - невозможно сформировать котировку из-за рыночных условий

### 6.2 Подтверждение конвертации
**Назначение:** Подтверждение ранее полученной котировки и выполнение операции конвертации.

**Метод и URL:** POST/convert

**Входные параметры:**
- идентификатор котировки

**Выходные данные:**
- идентификатор операции
- результат выполнения (успешно/не успешно)

**Основные ошибки:**
- 410 Gone - срок действия котировки истёк
- 400 Bad Request - недостаточно средств на момент подтверждения
- 409 Conflict - торговая пара стала недоступна
- 500 Internal Server Error - техническая ошибка выполнения операции

>*Ручка подтверждения должна быть идемпотентной по идентификатору котировки, чтобы исключить повторное выполнение конвертации при повторной отправке запроса.*
## 7. Жизненный цикл и статусы операции
### 7.1 Статусы операции:
- CREATED - котировка получена, операция ещё не подтверждена пользователем
- CONFIRMED - пользователь подтвердил котировку, начато исполнение операции
- SUCCESS - конвертация успешно выполнена, балансы обновлены
- FAILED - операция не выполнена, изменения балансов отсутствуют
- EXPIRED - срок действия котировки истёк до подтверждения пользователем

### 7.2 Переходы между статусами:
- CREATED → CONFIRMED - пользователь подтверждает котировку в пределах TTL
- CREATED → EXPIRED - TTL котировки истёк без подтверждения
- CONFIRMED → SUCCESS - все проверки пройдены, конвертация выполнена
- CONFIRMED → FAILED - операция не выполнена из-за ошибки или изменения условий

### 7.3 Неуспешное завершение операции:
- истечение срока действия котировки до подтверждения (статус EXPIRED)
- недостаточно средств на момент подтверждения
- торговая пара стала недоступна
- изменение рыночных условий или отсутствие ликвидности
- техническая ошибка при исполнении

## 9. Допущения и вопросы
### 9.1 Допущения:
1.	Не задаётся максимальная сумма актива.
2.	Котировка является фиксированной на весь срок действия TTL.
3.	Комиссия заранее известна системе.
4.	Операция конвертации не допускает частичного исполнения.
5.	Пользователь вводит сумму исходного актива, а сумма целевого рассчитывается системой.
6.	Операция атомарна - списание и начисление происходят в одной транзакции.

### 9.2 Вопросы перед началом реализации:
1.	Нужно ли отображать пользователю комиссию отдельно или только итоговую сумму?
2.	Должен ли пользователь иметь возможность указать сумму целевого актива вместо исходного?
3.	Какие требования к точности расчёта?
4.	Существуют ли ограничения на максимальный объём конвертации?
5.	Какое время действия котировки?
6.	Требуется ли резервирование средств пользователя на время действия котировки?

## 10. Пример OAS-контракта
Ниже приведён пример упрощённого OAS-контракта для функции мгновенной конвертации.
Контракт отражает основные сценарии взаимодействия клиента и сервера и может быть расширен при дальнейшей проработке требований.

```yaml
openapi: 3.0.3
info:
  title: Instant Conversion API
  version: 1.0.0

paths:
  /quote:			#эндпоинт получения котировки
    post:
      summary: Получение котировки
      description: |
        Возвращает котировку для мгновенной конвертации одного актива в другой.
        Котировка действует ограниченное время (TTL).
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required:		    #необходимые поля
                - fromAsset		#исходный актив (BTK)
                - toAsset 		#целевой актив (USDT)
                - amountFrom 	#сумма исходного актива
              properties: 		#характеристики полей
                fromAsset:
                  type: string 	 #строковое поле
                  example: "BTC" #пример актива
                  description: Код исходного актива
                toAsset:
                  type: string
                  example: "USDT"
                  description: Код целевого актива
                amountFrom:
                  type: string
                  example: "0.01"	#пример суммы исходного актива
                  description: Сумма исходного актива (строка для точности)
      responses:		#коды ответов или ошибок, которые могут вернуться
        "200":			#успех
          description: Котировка получена
          content:
            application/json:
              schema:
                type: object
                properties:
                  quoteId:		#получен идентификатор котировки
                    type: string
                    example: "q-123456"
                  price:		
                    type: string
                    example: "43000.12"
                    description: Цена целевого актива
                  rate:
                    type: string
                    example: "43000.12"
                    description: Курс конвертации
                  amountTo:
                    type: string
                    example: "429.50"
                    description: Сумма к получению после комиссии и округления
                  expiresAt:
                    type: string
                    format: date-time
                    example: "2025-01-01T12:00:00Z"
                    description: Время окончания действия котировки
        "404":
          description: Торговая пара недоступна
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/Error"
              examples:
                pairNotAvailable:
                  value:
                    error: "PAIR_NOT_AVAILABLE"
                    message: "Торговая пара недоступна"
        "400":			#с этим кодом могут вернуться 2 ошибки
          description: Ошибка валидации
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/Error"
              examples:
                amountTooSmall:
                  value:
                    error: "AMOUNT_TOO_SMALL"
                    message: "Задана котировка с суммой меньше минимальной"
                 insufficientBalance:
                  value:
                    error: "INSUFFICIENT_BALANCE"
                    message: "Недостаточно средств"
        "503":
          description: Котировка не может быть сформирована
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/Error"
              examples:
                quoteUnavailable:
                  value:
                    error: "QUOTE_UNAVAILABLE"
                    message: "Невозможно сформировать котировку"

  /convert:			#эндпоинт подтверждения конвертации
    post:
      summary: Подтверждение конвертации
      description: |
        Подтверждает выполнение операции конвертации по ранее полученной котировке.
        Ручка должна быть идемпотентной по quoteId.
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required:		    #необходимые поля
                - quoteId		#идентификатор котировки
              properties:
                quoteId:
                  type: string
                  example: "q-123456"
      responses:
        "200":			#успех
          description: Конвертация выполнена
          content:
            application/json:
              schema:
                type: object
                properties:
                  operationId:	#получен идентификатор операции
                    type: string
                    example: "op-987654"
                  status:		#статус операции
                    type: string
                    enum: [SUCCESS, FAILED]     #результат выполнения (успешно/не успешно)
                    example: "SUCCESS"		    #успех, например!
        "410":
          description: Срок действия котировки истёк
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/Error"
              examples:
                expired:
                  value:
                    error: "QUOTE_EXPIRED"
                    message: "Срок действия котировки истёк"
        "400":
          description: Недостаточно средств на момент подтверждения
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/Error"
              examples:
                insufficientBalance:
                  value:
                    error: "INSUFFICIENT_BALANCE"
                    message: "Недостаточно средств"
        "409":
          description: Торговая пара стала недоступна
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/Error"
              examples:
                pairUnavailable:
                  value:
                    error: "PAIR_NOT_AVAILABLE"
                    message: "Торговая пара недоступна"
        "500":
          description: Техническая ошибка выполнения операции
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/Error"
              examples:
                internalError:
                  value:
                    error: "INTERNAL_ERROR"
                    message: "Ошибка сервера"

components:
  schemas:
    Error:
      type: object
      properties:
        error:
          type: string
          description: Machine-readable error code
        message:
          type: string
          description: Human-readable error message
```
