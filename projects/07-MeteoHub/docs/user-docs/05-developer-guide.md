## 1. Назначение документа

Документ описывает архитектуру проекта MeteoHub, структуру кода и правила внесения изменений. Предназначен для разработчиков, которые будут поддерживать или расширять функциональность приложения. Включает подробное описание визуальных настроек дашборда (цвета, масштабы графиков, логика избранного).

## 2. Архитектура и стек

Проект состоит из трех основных слоев:
1. **REST API (FastAPI)** — принимает запросы от UI, обрабатывает данные, кэширует их в PostgreSQL и отдает в формате JSON.
2. **UI (Streamlit + Plotly)** — визуализирует данные, строит графики и диаграммы.
3. **СУБД (PostgreSQL)** — хранит кэш ответов внешних API и дневные агрегаты для аналитики.

**Внешние интеграции:**
*   **MET Norway** (`api.met.no`) — прогноз и текущая погода (формат GeoJSON).
*   **Open-Meteo Archive** (`archive-api.open-meteo.com`) — исторические данные.
*   **Nominatim** (`nominatim.openstreetmap.org`) — геокодинг (поиск координат по названию).

**Основной стек:** Python 3.14, FastAPI, Pydantic, Streamlit, Plotly, Pandas, PostgreSQL (psycopg 3), httpx, timezonefinder.

## 4. Запуск и отладка

1. Убедитесь, что активировано виртуальное окружение `.venv`.
2. Запустите API и UI одной командой (или через `run-all.bat`):
   ```cmd
   uvicorn app.main:app --reload
   streamlit run ui/app.py
   ```
3. **Отладка API:** Swagger UI доступен по адресу `http://127.0.0.1:8000/docs`. Там можно тестировать эндпоинты без UI.
4. **Отладка БД:** Используйте `psql` или pgAdmin. Полезные запросы:
   ```sql
   -- Проверить кэш
   SELECT kind, latitude, longitude, expires_at FROM weather_cache;
   -- Проверить дневные агрегаты
   SELECT date, temperature_max, wind_speed_max FROM weather_daily;
   ```

## 5. Работа с базой данных и кэшем

### 5.1. Кэширование координат
Таблица `geocode_cache` хранит результаты поиска городов. 
*   **Важно:** колонки `latitude` и `longitude` имеют тип `numeric(9, 6)`. При выборке из кэша в `app/services/cache.py` параметры **обязательно** приводятся к этому же типу (`%s::numeric(9, 6)`). Если этого не сделать, Python-float (с большим числом знаков) не совпадет с округленным значением в БД, и кэш будет всегда промахиваться.

### 5.2. Кэширование погоды и агрегация
Функция `get_or_fetch_met_forecast` в `cache.py` не только сохраняет сырой GeoJSON от MET Norway в `weather_cache`, но и вызывает `aggregator.extract_daily()`. Этот метод пересчитывает почасовые данные в дневные максимумы/минимумы и сохраняет их в таблицу `weather_daily` через `UPSERT`.

## 6. Кастомизация UI (Streamlit)

Все настройки интерфейса находятся в `ui/app.py`.

### 6.1. Город по умолчанию
При первом запуске приложение открывает Новосибирск. Чтобы это изменить, найдите в `ui/app.py` инициализацию состояния сессии:
```python
if "selected_city" not in st.session_state:
    st.session_state["selected_city"] = "Новосибирск"
    st.session_state["search_results"] = []
    st.session_state["selectbox_city"] = "Новосибирск"
```

### 6.2. Цвета в блоке «Аналитика»
Цвета плашек задаются встроенными методами Streamlit. В функции `tab_analytics`:
*   `st.error(...)` — **красный** (Самый тёплый день).
*   `st.success(...)` — **зелёный** (Самый дождливый день).
*   `st.info(...)` — **синий** (Самый холодный день).
*   `st.warning(...)` — **жёлтый** (Самый ветреный день).

### 6.3. Градиент температуры на графике
Мы используем кастомную цветовую шкалу (по мотивам Яндекс.Погоды) и фиксированный диапазон от -40 до +40 °C.
В блоке `tab_forecast` найдите переменную `yandex_scale`. Она представляет собой список кортежей `(позиция, цвет_hex)`. Если нужно изменить цвета — правьте этот список.
Параметр `range_color=[-40, 40]` в `px.scatter` гарантирует, что 0 °C всегда будет зеленым, независимо от того, какие температуры попали в текущий прогноз.

### 6.4. Роза ветров
Роза ветров строится с помощью `px.bar_polar`. 
*   **Диапазон шкалы:** В `fig_wind.update_layout` параметр `radialaxis=dict(range=[0, 9])` фиксирует максимальную скорость ветра на графике до 9 м/с. Если нужно увеличить, измените число `9`.
*   **Подписи сторон света:** Словарь `compass` переводит градусы (0, 22.5, 45...) в текст (С, ССВ, СВ...). Ось `angularaxis` использует `tickvals` и `ticktext` для отображения букв вместо цифр.

### 6.5. Логика «Избранного»
Избранное хранится локально в файле `ui/favorites.json` (в корне папки `ui`). 
*   **Структура файла:** список словарей `[{"short_name": "Дом", "full_name": "Новосибирск, Новосибирская область, Россия"}]`.
*   **Синхронизация:** При клике на город в избранном мы обновляем `st.session_state["selected_city"]` и `st.session_state["selectbox_city"]`, а затем принудительно вызываем `st.rerun()`. Это предотвращает баг Streamlit, когда интерфейс не обновляется с первого клика при переключении вкладок.
*   **Кнопки действий:** В кнопках переименования и удаления используются стандартные эмодзи (`✏️`, `🗑️`). Для их корректного центрирования в узких колонках применяется параметр `use_container_width=True`.

### 6.6. Часовые пояса
Время от MET Norway приходит в UTC. Чтобы графики строились по местному времени:
1. При геокодинге библиотека `timezonefinder` определяет пояс по координатам и сохраняет его в БД (например, `Asia/Novosibirsk`).
2. API возвращает это поле в ответе (поле `timezone`).
3. В Streamlit при построении графика время конвертируется: `df_hourly["time"].dt.tz_convert(tz_str)`.

## 7. Как добавить новый эндпоинт

1. Создайте Pydantic-модель ответа в `app/schemas.py`.
2. Если нужна новая логика работы с внешним API — добавьте функцию в соответствующий файл в `app/services/`.
3. Создайте функцию в `app/routers/weather.py` (или `analytics.py`) с декоратором `@router.get(...)`.
4. Укажите `response_model=ВашаМодель` и добавьте описание (`summary`, `description`) — они появятся в Swagger.
5. Если эндпоинт требует поиска города, добавьте параметр `geo: dict = Depends(resolve_city)`.
6. Добавьте вызов нового эндпоинта в `ui/app.py`, если требуется визуализация.
