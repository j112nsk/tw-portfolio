## 1. Назначение документа

Единый словарь терминов и сокращений, используемых в проекте MeteoHub. Документ обеспечивает единообразие терминологии во всех артефактах (документация, интерфейс, код, API) и служит точкой входа для новых участников команды.

## 2. Термины предметной области

| Термин | Определение |
|--------|-------------|
| **Погода** | Совокупность метеорологических параметров (температура, ветер, осадки, влажность, давление) в конкретной точке в конкретное время. |
| **Текущая погода** | Метеорологические условия на момент запроса или ближайший час (в зависимости от источника). |
| **Прогноз** | Набор метеорологических параметров, ожидаемых в будущем. В MeteoHub отображается в виде почасового графика и сводки по дням. |
| **История (архив)** | Ретроспективные метеорологические данные за прошедшие периоды. |
| **Аналитика** | Сводные агрегаты за выбранный период: самый тёплый/холодный день, день с максимальными осадками и самый ветреный день. |
| **Роза ветров** | Векторная диаграмма, показывающая распределение направлений и скоростей ветра. В MeteoHub строится по часовым данным прогноза. |
| **Часовой пояс** | Локальное время населённого пункта (например, `Asia/Novosibirsk`). В API все данные приходят в UTC, но на графиках отображаются в локальном времени выбранного города. |
| **WMO-код** | Международный стандарт числового кодирования погодных явлений (ясно, дождь, снег и т.д.). В UI преобразуется в текстовое описание через модуль `app/wmo.py`. |

## 3. Технические термины и технологии

| Термин | Определение |
|--------|-------------|
| **REST API** | Архитектурный стиль взаимодействия компонентов распределённого приложения в сети. В MeteoHub реализован на FastAPI. |
| **FastAPI** | Python-фреймворк для создания REST API, автоматически генерирующий OpenAPI-спецификацию (Swagger UI). |
| **Swagger UI** | Интерактивная веб-документация к API, доступная по адресу `http://127.0.0.1:8000/docs`. |
| **Pydantic** | Библиотека Python для валидации данных и управления настройками. В MeteoHub используется для описания схем запросов и ответов API. |
| **Streamlit** | Python-фреймворк для быстрого создания интерактивных дашбордов. Используется как UI в MeteoHub. |
| **Plotly** | Библиотека для построения интерактивных графиков. Отвечает за линейные графики, столбчатые диаграммы и розу ветров. |
| **PostgreSQL** | Реляционная СУБД, используемая для кэширования ответов внешних API и хранения дневных агрегатов. |
| **Кэш** | Временное хранилище данных для снижения количества запросов к внешним API. В MeteoHub реализован на базе таблиц `geocode_cache` и `weather_cache`. |
| **TTL (Time To Live)** | Время жизни записи в кэше. Настраивается в `.env` (параметры `CACHE_TTL_GEOCODE`, `CACHE_TTL_WEATHER`). |

## 4. Внешние интеграции

| Термин | Определение |
|--------|-------------|
| **MET Norway** | Норвежский метеорологический институт. Источник прогнозов и текущей погоды (API `api.met.no`). Требует передачи заголовка `User-Agent` с контактом разработчика. |
| **Open-Meteo** | Открытый погодный API. В MeteoHub используется только для получения исторических данных (`archive-api.open-meteo.com`). |
| **Nominatim** | Открытый геокодер на базе OpenStreetMap. Используется для поиска координат населённых пунктов. Требует `User-Agent` и ограничивает частоту запросов (1 запрос в секунду). |
| **Геокодинг** | Процесс преобразования названия населённого пункта в географические координаты (широту и долготу). |
| **Агрегатор** | Модуль `app/services/aggregator.py`, который преобразует сырые почасовые данные MET Norway в дневные агрегаты и заполняет таблицу `weather_daily`. |
