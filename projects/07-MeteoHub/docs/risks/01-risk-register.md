## 1. Назначение документа

Документ содержит перечень выявленных рисков проекта, оценку их вероятности и влияния, а также перечень мер по их предотвращению или минимизации последствий. Реестр актуален на момент выпуска MVP (версия 1.0).

## 2. Методология оценки

Риски оцениваются по шкале от 1 до 3:
*   **Вероятность (P):** 1 — низкая, 2 — средняя, 3 — высокая.
*   **Влияние (I):** 1 — низкое, 2 — среднее, 3 — высокое.
*   **Критичность (P × I):** от 1 до 9. Риски с критичностью ≥ 6 требуют обязательного плана митигации.

## 4. Реагирование на инциденты

В случае падения одного из внешних сервисов (R-01, R-03):
1. Пользователь видит сообщение об ошибке в UI (красная плашка).
2. API возвращает HTTP 502 (Bad Gateway).
3. Если проблема временная, повторный запрос через несколько минут восстановит работу.
4. При долговременной блокировке требуется замена источника данных в `app/services/` (архитектура позволяет сделать это без переписывания UI).
