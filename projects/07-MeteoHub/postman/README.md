# Postman-коллекция MeteoHub

В этой папке находится файл `MeteoHub.postman_collection.json` — готовая коллекция запросов для тестирования REST API.

## 1. Импорт коллекции (веб-версия)

1. Откройте [Postman Web](https://web.postman.co/) в браузере и войдите в свой аккаунт.
2. В левом верхнем углу нажмите кнопку **Import** (Импорт).
3. Перетащите файл `MeteoHub.postman_collection.json` в открывшееся окно или выберите его через файловый менеджер.
4. После импорта в левой панели появится коллекция **MeteoHub API** с папками «Служебные», «Геокодинг», «Погода» и «Аналитика».

## 2. Настройка доступа к локальному API (Desktop Agent)

Поскольку API работает на вашем компьютере (`http://127.0.0.1:8000`), веб-версии Postman нужен **Postman Desktop Agent**. Он выступает посредником между браузером и вашим `localhost`, обходя ограничения CORS.[reference:1]

### 2.1. Установка агента
1. Скачайте и установите **Postman Desktop Agent** с [официальной страницы](https://www.postman.com/downloads/).[reference:2]
2. Запустите агент. Он будет работать в фоне (иконка в системном трее).

### 2.2. Переключение на агента в веб-версии
1. Вернитесь в браузер с открытым Postman Web.
2. В **нижней части** окна (в строке состояния) найдите селектор агента.
3. Переключите его с **Cloud Agent** на **Desktop Agent**.[reference:3]
4. Если переключатель неактивен, убедитесь, что агент запущен, и обновите страницу.

> **Важно:** Без этого шага любые запросы к `http://127.0.0.1:8000` будут завершаться ошибкой `Error: connect ECONNREFUSED` или `Could not send request`.

### **Автономная демонстрация.** 
Если вы хотите показать работу с внешними API без развёртывания локального сервера, используйте коллекцию MeteoHub_Direct_APIs.postman_collection.json. Она не требует Desktop Agent и работает в облаке Postman.

## 3. Настройка переменной `baseUrl`

Коллекция использует переменную `{{baseUrl}}`, чтобы не дублировать адрес в каждом запросе.

1. Выделите коллекцию **MeteoHub API** в левой панели.
2. Перейдите на вкладку **Variables** (Переменные).
3. Убедитесь, что для переменной `baseUrl` установлено значение:
   - **Initial Value:** `http://127.0.0.1:8000`
   - **Current Value:** `http://127.0.0.1:8000`
4. Если вы изменили порт API (например, на `8001`), обновите значение в обоих полях.

## 4. Запуск отдельных запросов

1. Убедитесь, что API запущен (`run-api.bat`).
2. Откройте любой запрос из коллекции (например, `GET /current`).
3. Нажмите кнопку **Send**.
4. В нижней части окна отобразится JSON-ответ от API с кодом `200 OK`.

Вы можете менять параметры запроса (например, `city` или `days`) прямо в интерфейсе Postman.

## 5. Пакетный запуск (Collection Runner)

Для последовательного выполнения всех запросов коллекции используйте **Collection Runner**.

1. Нажмите на три точки (**...**) рядом с названием коллекции **MeteoHub API**.
2. Выберите **Run collection** (Запустить коллекцию).
3. В открывшемся окне:
   - **Run order:** оставьте `Run all requests in order`.
   - **Data:** не заполняйте (у нас нет внешнего файла данных).
   - **Delay:** можно установить `100` мс между запросами, чтобы не перегружать API.
4. Нажмите кнопку **Run MeteoHub API** (внизу справа).
5. Postman последовательно выполнит все запросы и покажет сводку: сколько прошло успешно, сколько упало, и время выполнения.

> **Примечание:** В онлайн-версии для Collection Runner также требуется активный **Desktop Agent**. Если вы видите ошибку, вернитесь к шагу 2.

## 6. Возможные проблемы и решения

| Проблема | Причина | Решение |
|----------|---------|---------|
| `Could not send request` | Не выбран Desktop Agent | Переключите агент в нижней строке на **Desktop Agent** и убедитесь, что он запущен. |
| `ECONNREFUSED` | API не запущен или порт занят | Запустите `run-api.bat` и проверьте, что в консоли нет ошибок. |
| `CORS error` | Запрос идёт через Cloud Agent | Переключитесь на Desktop Agent. |
| `404 Not Found` | Неверное имя эндпоинта | Проверьте путь в URL (например, `/current`, а не `/weather`). |
| `502 Bad Gateway` | Внешний API (MET Norway, Nominatim) недоступен | Повторите запрос через минуту. Если ошибка повторяется, проверьте подключение к интернету. |

## 7. Проверка живости API

Самый простой тест — запрос `GET /health` из папки «Служебные». Если он возвращает `{"status":"ok"}`, значит API запущен и доступен, и можно переходить к остальным запросам.
