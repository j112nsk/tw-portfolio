## 1. Назначение документа

Описать, как логическая модель реализована в PostgreSQL: типы данных, ограничения, триггеры,
индексы и порядок применения миграций. Документ содержит словарь данных и таблицу соответствия
правил целостности (INV-01–INV-20) их реализации.

## 2. Среда и соглашения

- **СУБД:** PostgreSQL. DDL написан для версии 14 и новее; на компьютере автора установлена
  версия 18 (PM-01).
- **Базы данных:** рабочая `job_search_crm` и демонстрационная `job_search_crm_demo` (PM-09),
  кодировка UTF8, схема `public`. Роль приложения `crm_app`, пароль хранится в `.env`.
- **Имена:** таблицы и поля в `snake_case` на английском; первичный ключ всегда `id` (у связей
  составной); внешний ключ называется `<сущность>_id`.
- **Имена ограничений:** `<таблица>_<суть>_chk` (проверка), `<таблица>_<суть>_uk` (уникальность).
  Внешние ключи получают имена PostgreSQL по умолчанию (`<таблица>_<поле>_fkey`).
- **Прочие объекты:** индексы `ix_<таблица>_<суть>`, функции триггеров `fn_<таблица>_<суть>`,
  триггеры `<таблица>_<суть>`.
- **Значения справочников** приложение и запросы выбирают по полю `code`, а не по числовому
  `id` (PM-03).

## 3. Типы данных

| Логический тип | Физический тип | Обоснование |
|----------------|----------------|-------------|
| Идентификатор справочника | `smallint generated always as identity` | Справочники малы; значения формирует СУБД |
| Идентификатор рабочих записей | `bigint generated always as identity` | Стандартный запас; ручная подстановка `id` запрещена |
| Идентификатор навыка | `integer generated always as identity` | Навыков может быть сотни |
| Текст | `text` | В PostgreSQL `varchar(n)` не даёт преимуществ; длины бизнес-правилами не заданы |
| Дата этапа или события | `date` | Время не хранится (D21) |
| Момент записи | `timestamptz` | Однозначный момент независимо от часового пояса (NFR-06) |
| Флаг | `boolean` | — |
| Деньги | `integer` | Целые рубли «на руки» (D15) |
| Инициатор, тип статуса | `text` + `check` | Фиксированный набор значений, от которого зависят правила; в справочник не выносится |

## 4. Словарь данных

### 4.1. Простые справочники

Одинаковую структуру имеют `directions`, `vacancy_sources`, `employer_types`,
`employment_formats`, `rejection_reasons`.

| Поле | Тип | NULL | Ограничения | Назначение |
|------|-----|------|-------------|------------|
| `id` | smallint, identity | нет | PK | Идентификатор |
| `code` | text | нет | Уникален; формат `^[A-Z][A-Z0-9_]*$` | Стабильный код для приложения и запросов |
| `name_ru` | text | нет | Не пустой | Название в интерфейсе |
| `sort_order` | smallint | нет | — | Порядок вывода |

### 4.2. `channels` — каналы отклика и общения

Поля `id`, `code`, `name_ru`, `sort_order` как в 4.1, плюс:

| Поле | Тип | NULL | Ограничения | Назначение |
|------|-----|------|-------------|------------|
| `is_apply_channel` | boolean | нет | — | `true`: каналом можно откликнуться (hh.ru, Telegram, почта); `false`: только канал общения (телефон) |

### 4.3. `statuses` — статусы процесса

Поля `id`, `code`, `name_ru`, `sort_order` как в 4.1, плюс:

| Поле | Тип | NULL | Ограничения | Назначение |
|------|-----|------|-------------|------------|
| `kind` | text | нет | `stage` или `outcome` | Этап или итог |
| `stage_order` | smallint | да | Больше 0; уникален | Порядок этапа (SR11) |
| `is_required_stage` | boolean | да | — | Обязательный этап воронки (SR11) |
| `in_funnel` | boolean | да | — | Участвует ли этап в воронке; у «Отклика» `false` (D25) |

Три последних поля заполнены у этапов и пусты у итогов (`statuses_stage_chk`).

### 4.4. `job_processes` — процесс

| Поле | Тип | NULL | Ограничения и ссылки | Назначение |
|------|-----|------|---------------------|------------|
| `id` | bigint, identity | нет | PK | Идентификатор |
| `direction_id` | smallint | нет | FK → `directions` | Направление поиска |
| `initiator` | text | нет | `applicant` или `employer`; не меняется (триггер) | Кто начал процесс |
| `company_name` | text | нет | Не пустой | Компания |
| `vacancy_title` | text | нет | Не пустой | Название вакансии |
| `vacancy_url` | text | да | Если задана, начинается с `http://` или `https://`, без пробелов | Ссылка на вакансию (D31) |
| `vacancy_source_id` | smallint | да | FK → `vacancy_sources`; обязателен для `applicant`, пуст для `employer` | Источник вакансии |
| `apply_channel_id` | smallint | да | FK → `channels`; триггер: только каналы отклика; обязателен для `applicant`, пуст для `employer` | Канал отклика |
| `communication_channel_id` | smallint | нет | FK → `channels` | Канал общения |
| `employer_type_id` | smallint | да | FK → `employer_types` | Тип работодателя |
| `employment_format_id` | smallint | да | FK → `employment_formats` | Формат трудоустройства |
| `salary_from` | integer | да | Больше 0; не больше `salary_to` | Вилка «от», руб. на руки |
| `salary_to` | integer | да | Больше 0 | Вилка «до», руб. на руки |
| `contact_name` | text | да | — | Имя контакта |
| `contact_position` | text | да | — | Должность контакта |
| `note` | text | да | — | Комментарий |
| `status_id` | smallint | нет | FK → `statuses`; поддерживается триггером | Текущий статус |

Даты в таблице нет: дата начала процесса вычисляется по истории (DQ7).

## 6. Триггеры

| Триггер | Таблица и событие | Что делает |
|---------|-------------------|------------|
| `job_processes_check_channels` | `job_processes`, до вставки и изменения `apply_channel_id` | Отклоняет канал с `is_apply_channel = false` |
| `job_processes_protect_initiator` | `job_processes`, до изменения `initiator` | Запрещает менять инициатора после создания |
| `process_status_history_check_rejection` | `process_status_history`, до вставки и изменения `status_id`, `rejection_reason_id` | Отклоняет причину отказа у записей, кроме «Отказ работодателя» и «Мой отказ» |
| `process_status_history_sync_status` | `process_status_history`, после вставки, удаления и изменения `status_id`, `recorded_at` | Записывает в `job_processes.status_id` статус последней записи истории (порядок: `recorded_at`, затем `id`) |
| `process_status_history_protect_last` | `process_status_history`, до удаления | Запрещает удалить единственную запись истории процесса; при каскадном удалении процесса (вложенный вызов, `pg_trigger_depth() > 1`) проверка не выполняется |

Порядок работы приложения при создании процесса: в одной транзакции вставить строку
`job_processes` с начальным статусом, затем первую запись истории (и тестовое задание, если
первым выдано тестовое). Дальше `status_id` вручную не меняется.

## 8. Миграции

Схема создаётся нумерованными SQL-файлами в `db/schema/`. Каждый файл применяется один раз, в
одной транзакции, по порядку номеров; применённые файлы не правятся, изменение схемы оформляется
новым файлом (PM-07).

| Файл | Содержание |
|------|------------|
| `001_create_schema.sql` | Справочники, рабочие таблицы, индексы, комментарии |
| `002_seed_reference_data.sql` | Значения справочников (US-10) |
| `003_triggers.sql` | Функции и триггеры (раздел 6) |

Миграции применяет скрипт `db/migrate.py`: создаёт служебную таблицу `schema_migrations`
(версия, имя файла, контрольная сумма, момент применения), запускает ещё не применённые файлы по
порядку и останавливается на первой ошибке; если применённый файл изменили, отказывается
работать. Проверку базы выполняет `tests/smoke_db.py`: все проверки идут в транзакции, которая
откатывается.

## 9. Принятые решения

| ID | Решение |
|----|---------|
| PM-01 | Используется PostgreSQL; DDL рассчитан на версию 14 и новее; у автора установлена версия 18. Базы `job_search_crm` и `job_search_crm_demo`, кодировка UTF8, схема `public`, роль приложения `crm_app` |
| PM-02 | Текст хранится типом `text`; идентификаторы формирует СУБД (`generated always as identity`), ручная подстановка запрещена |
| PM-03 | Значения справочников выбираются по полю `code`, а не по числовому `id` |
| PM-04 | Правила выражены ограничениями везде, где это возможно; триггеры только для межтабличных правил и неизменяемости (пять триггеров); остальное проверяет приложение и запросы согласованности |
| PM-05 | Текущий статус процесса ведёт триггер (INV-10): приложение указывает только начальный статус при создании процесса |
| PM-06 | Набор индексов минимален (восемь индексов и один уникальный по навыкам), обоснован сценариями из историй |
| PM-07 | Миграции: нумерованные SQL-файлы, применяются один раз и не правятся; для изменений создаётся новый файл |
| PM-08 | Словарь данных дублируется в базе комментариями к таблицам и ключевым полям (`comment on`) |
| PM-09 | Демонстрационные данные хранятся в отдельной базе `job_search_crm_demo` с теми же миграциями; режим выбирается переменной `PGDATABASE` в `.env` (UQ3 пользовательских историй) |
