## 1. О документе

Единый словарь терминов проекта: предметная область (поиск работы), модель данных, статусы и правила, аналитика, технические понятия. Термины расположены по группам и внутри каждой — по алфавиту.

В определениях указаны источники: решения (D), правила (SR, INV, DM, PM), бизнес-вопросы (Q), пользовательские истории (US), риски (R). Ссылки на документы — в конце раздела.

## 2. Предметная область

**Аутстафф** (`OUTSTAFF`) — компания-посредник, которая оформляет сотрудника в свой штат и «сдаёт в аренду» заказчику. Одно из значений справочника «Тип работодателя» (D20).

**Вакансия** — предложение работы от конкретного работодателя. В системе не является отдельной сущностью: хранится как текстовое поле процесса (`vacancy_title`) вместе со ссылкой (`vacancy_url`, необязательна, D31).

**Входящий процесс** — процесс, который начал работодатель: он написал первым, вакансия релевантна, стороны назначили этап. Инициатор — `employer` (D11).

**ГПХ (ИП/СЗ)** — гражданско-правовой договор; работает либо с индивидуальным предпринимателем (**ИП**), либо с самозанятым (**СЗ**). Одно из значений справочника «Формат трудоустройства» (D20). Все суммы таких вилок приводятся к «на руки» вами самостоятельно (D15).

**Инициатор** — кто начал процесс: `applicant` («Я откликнулся») или `employer` («Работодатель написал первым»). После создания не меняется (INV-19, UQ1).

**Кадровое агентство** (`STAFFING_AGENCY`) — компания, подбирающая кандидатов для других работодателей. Одно из значений справочника «Тип работодателя» (D20).

**Направление** — одно из двух направлений поиска: **системный / бизнес-аналитик** (SA/BA) или **технический писатель** (TW). Хранится в справочнике `directions`; каждая вакансия относится к одному направлению (D1). Гибридные вакансии СА/БА/Fullstack относятся к SA/BA (D7).

**Начатый откликом** — процесс с инициатором `applicant`: соискатель сам откликнулся, и впоследствии было назначено интервью или выдано тестовое (D23).

**Отклик** — отправка резюме и (иногда) сопроводительного письма в ответ на вакансию. Около 70 откликов в неделю у автора; в системе не фиксируются (ADR-001, D23). Отдельный статус `APPLIED` в воронке не участвует (D25).

**Прямой работодатель** (`DIRECT`) — компания, нанимающая сотрудника в свой штат. Одно из значений справочника «Тип работодателя» (D20).

**Резюме** — одно на каждое направление, без версий (D2).

**Сопроводительное письмо** — необязательное вложение к отклику. Не фиксируется в системе (D28).

**Соискатель** — основной (и единственный) пользователь системы. Ведёт поиск работы по двум направлениям.

**ТК** — трудовой договор по Трудовому кодексу. Одно из значений справочника «Формат трудоустройства» (D20).

## 3. Процесс и его состояния

**Дата записи** (`recorded_at`) — момент создания записи истории; проставляется автоматически при сохранении. В интерфейсе отображается как «Дата записи», сортировка истории — по ней (свежие сверху).

**Дата этапа** (`stage_date`) — дата, которую вы вводите вручную при назначении этапа: прошедшая, сегодняшняя или будущая. Без времени (D21).

**Запланированный этап** — запись истории со статусом-этапом и датой не раньше сегодняшней **или** несданное тестовое со сроком сдачи не раньше сегодняшней даты. Тестовое без срока или с уже прошедшим сроком запланированным не считается (SR13, DQ5).

**Закрытый процесс** — процесс, текущий статус которого — итог (см. «Итог»).

**Итог** — статус типа `outcome`, завершающий процесс. Всего пять: `OFFER_ACCEPTED` (Оффер принят), `OFFER_DECLINED` (Оффер отклонён мной), `REJECTED_BY_EMPLOYER` (Отказ работодателя), `WITHDRAWN_BY_ME` (Мой отказ), `NO_RESPONSE` (Нет ответа).

**Квалифицированный процесс** — то же, что «процесс». См. определение ниже.

**Открытый процесс** — процесс, текущий статус которого — этап (не итог).

**Процесс** (в узком смысле — «квалифицированный процесс») — основная сущность системы (`job_processes`). Это либо отклик, по которому назначено интервью или выдано тестовое, либо входящий контакт, по которому работодатель вышел первым и стороны назначили этап. Отклики без этапа в системе не хранятся (ADR-001, D23).

**Процесс достиг этапа** — по истории процесса есть запись-этап с `stage_order` не меньше порядка целевого этапа. Для обязательных этапов (HR-интервью, техническое собеседование, оффер) это правило; для необязательных (Знакомство с командой, СБ) — учитывается только фактическое наличие записи (SR11).

**Тестовое задание** (`test_assignments`) — тестовое, полученное в ходе процесса. Не является статусом процесса: это **событие** внутри любого этапа. Хранит дату получения (`received_on`), срок сдачи (`due_on`, необязательно), дату сдачи (`submitted_on`), результат (`result_note`) и статус, действовавший на момент получения (SR7, DQ5).

**Этап** — статус типа `stage`, соответствующий шагу отбора. Всего шесть: `APPLIED` (Отклик), `HR_INTERVIEW` (HR-интервью), `TECH_INTERVIEW` (Техническое собеседование), `TEAM_MEETING` (Знакомство с командой), `SECURITY_CHECK` (СБ), `OFFER` (Оффер).

## 4. Этапы отбора

**Знакомство с командой** (`TEAM_MEETING`) — необязательный этап: встреча с будущими коллегами. В воронке учитывается только если запись действительно была (SR11).

**HR-интервью** (`HR_INTERVIEW`) — первичное интервью с HR. Обязательный этап; начальный статус по умолчанию (D25). Начиная с него становится доступен ввод навыков вакансии (D8, SR8).

**Оффер** (`OFFER`) — предложение работы. Обязательный этап. Дата в записи означает срок ответа на оффер.

**Отклик** (`APPLIED`) — начальный статус процесса, когда **первым** выдано тестовое задание (D25). В воронке не участвует; такие процессы показываются отдельной строкой «только тестовое».

**СБ** (`SECURITY_CHECK`) — необязательный этап: проверка службы безопасности. В воронке учитывается только если запись действительно была (SR11).

**Техническое собеседование** (`TECH_INTERVIEW`) — обязательный этап: проверка профессиональных знаний и навыков.

## 5. Источники и каналы

**Источник вакансии** (`vacancy_sources`) — где вы нашли вакансию: hh.ru, Telegram-канал, сайт компании, другое. Заполняется только для процессов, начатых откликом; для входящих не заполняется (D11, D12, INV-02).

**Канал общения** (`communication_channel_id`) — где идёт переписка с работодателем: hh.ru, Telegram, почта, телефон. Обязателен всегда (INV-03, TQ10). Может не совпадать с каналом отклика (D12).

**Канал отклика** (`apply_channel_id`) — как вы отправили отклик: hh.ru, Telegram, почта. Заполняется только для процессов, начатых откликом; должен ссылаться на канал с признаком `is_apply_channel = true` (INV-04). Телефон каналом отклика не бывает.

## 6. Навыки

**Навык** (`skills`) — единица требований вакансии или компетенции в вашем профиле. Хранится в общем справочнике `skills`. Уникален **без учёта регистра и пробелов по краям** (INV-14, US-11): `SQL`, `sql` и ` SQL ` — один и тот же навык.

**Навыки вакансии** (`process_skills`) — навыки, указанные работодателем у конкретного процесса. Вводятся вручную начиная с HR-интервью (D8, SR8). Сохраняются даже если HR-интервью позже удалено из истории, но в рейтинг Q5/Q6 такие процессы не попадают (INV-17).

**Профиль навыков** (`profile_skills`) — ваш набор навыков по направлению. Ведётся отдельно для SA/BA и TW (D3). Используется в Q6 для поиска пробелов.

**Пробел в навыках** — навык, встречающийся у процессов направления, но отсутствующий в вашем профиле этого направления (Q6).

## 7. Аналитика

**Бизнес-вопрос** (Q1–Q13) — вопрос, на который должна отвечать система. Список — в Vision & Scope; расчёт каждого — в SQL-запросах `db/queries/` и на дашборде. Q10 и Q11 сняты (D23, D28).

**Воронка** — последовательность обязательных этапов отбора, по которой считается конверсия: HR-интервью → техническое собеседование → оффер. Необязательные этапы (знакомство с командой, СБ) показываются числом процессов без конверсии. Статус «Отклик» в воронку не входит (D25, SR11).

**Календарные дни** — обычные дни, без исключения выходных и праздников. Дни между этапами считаются календарными (D29, SR12).

**Конверсия** — доля процессов, достигших следующего этапа, от числа процессов на предыдущем. Считается по истории, не по текущему статусу (D14).

**Малая выборка** — N (число процессов в показателе) меньше 10. На дашборде помечается; выводы делать осторожно (R2).

**Размер выборки (N)** — число процессов, по которым построен показатель. Показывается рядом с каждым показателем (R2).

**Середина вилки** — среднее границ вилки «на руки». Если задана одна граница, используется она. Применяется в Q7 (US-18).

## 8. Технические термины

**.env** — файл в корне проекта с параметрами подключения к PostgreSQL (`PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`). Исключён из Git; в репозитории только образец `.env.example` (NFR-04).

**ADR** (Architecture Decision Record) — запись архитектурного решения. В проекте: `docs/adr/ADR-001-record-only-qualified-processes.md`.

**Autocommit** — режим соединения с PostgreSQL, в котором каждый оператор коммитится сразу. Используется в `db/connection.py`; записывающие функции приложения полагаются на это поведение.

**dump / restore** — не используется в проекте. Для переноса данных — стандартные средства PostgreSQL (`pg_dump`, `pg_restore`).

**Миграция** — SQL-файл из `db/schema/NNN_*.sql`, меняющий схему базы. Применяется один раз, в одной транзакции; применённые файлы не правятся, изменения — новым файлом (PM-07). Учёт миграций ведёт `db/migrate.py` в таблице `schema_migrations` с контрольной суммой файла.

**Орм (ORM)** — библиотека, отображающая таблицы в объекты. Не используется: в проекте обычный SQL через `psycopg` 3 (в соглашениях PM-02, PM-03).

**Правило целостности (INV)** — правило, которое обязано соблюдаться в базе. Реализуется ограничением, триггером, приложением или проверочным запросом. Полный список — в логической модели, раздел 6.

**Роль** (`crm_app`) — пользователь PostgreSQL, под которым работает приложение. Владеет базами, но не имеет права создавать новые (PQ1).

**Схема** (`public`) — стандартное пространство имён объектов в PostgreSQL. Используется без изменений.

**Триггер** — функция базы, выполняющаяся до/после изменений в таблице. В проекте пять триггеров: проверка канала отклика, защита инициатора, причина отказа только у записей об отказе, синхронизация текущего статуса, защита единственной записи истории (003_triggers.sql).

**Streamlit** — Python-библиотека, на которой построен интерфейс приложения (страницы, формы, таблицы, навигация). Версия ≥ 1.52 — первая с поддержкой Python 3.14.

**Altair** — библиотека для декларативных графиков; используется на дашборде для круговых диаграмм воронки. Приходит как зависимость Streamlit.

**psycopg 3** — драйвер PostgreSQL для Python. Соединение открывается в `db/connection.py` с `autocommit=True`, `client_encoding='UTF8'`.

**Юнит-экономика** — не относится к проекту. Используется в бизнес-контексте; в этом глоссарии не определяется.
