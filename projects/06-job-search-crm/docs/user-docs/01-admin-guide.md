## 1. Назначение документа

Инструкция по установке и запуску Job Search CRM на чистой Windows 10 или 11. Рассчитана на человека, который раньше не работал с этим проектом.

Документ проверен на машине автора (Windows 11, Python 3.14, PostgreSQL 18.6, PowerShell). На других конфигурациях шаги те же; версии, отличные от примеров, нужно подставить свои (минимум — Python 3.11 и PostgreSQL 14).

**Время на прохождение:** около 30 минут, включая скачивание и установку Python и PostgreSQL.

## 2. Что понадобится

- Компьютер с Windows 10 или Windows 11, права администратора.
- Доступ в интернет.
- Свободное место на диске: около 1 ГБ.
- Терминал PowerShell (открывается в VS Code через **Терминал → Новый терминал** или из меню **Пуск → Windows PowerShell**).

По ходу установки понадобятся:

| Компонент | Версия | Где взять |
|-----------|--------|-----------|
| Python | 3.11 или новее | https://www.python.org/downloads/windows/ |
| PostgreSQL | 14 или новее | https://www.postgresql.org/download/windows/ |
| Git | любая актуальная | https://git-scm.com/download/win |

## 3. Шаг 1. Установить Python

1. Откройте страницу загрузки Python.
2. Скачайте установщик последней версии для Windows (например, `python-3.14.0-amd64.exe`).
3. Запустите установщик. **Обязательно** отметьте внизу галочку **Add python.exe to PATH**.
4. Нажмите **Install Now**, дождитесь окончания, закройте окно.

Проверка. Откройте PowerShell и введите:

```powershell
python --version
```

Ожидается строка вида `Python 3.14.0`. Если команда не найдена — переустановите Python и не забудьте про галочку **Add python.exe to PATH** (или перезапустите PowerShell, если установка прошла только что).

## 4. Шаг 2. Установить PostgreSQL

1. Откройте страницу загрузки PostgreSQL.
2. Скачайте установщик для Windows (EDB installer), запустите его.
3. На шаге **Password** задайте пароль для суперпользователя `postgres`. **Запомните его**: он понадобится один раз при создании роли приложения.
4. Остальные шаги — по умолчанию. Порт `5432`, локаль `Russian_Russia.1251` или `C` — не важно.
5. По завершении установщик предложит **Stack Builder** — можно закрыть, он не нужен.

Проверка. По умолчанию `psql` не добавляется в PATH. В новом окне PowerShell выполните:

```powershell
$env:Path += ";C:\Program Files\PostgreSQL\18\bin"
psql --version
```

Если у вас другая версия PostgreSQL — подставьте её номер вместо `18`. Ожидается строка вида `psql (PostgreSQL) 18.6`.

> Команда `$env:Path += ...` действует только в текущем окне PowerShell. Если открыть новое окно, PATH вернётся к прежнему значению; добавление в PATH через свойства системы — на ваше усмотрение, для проекта это не обязательно.

## 6. Шаг 4. Виртуальное окружение и зависимости

Виртуальное окружение изолирует библиотеки проекта от остальной системы.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Ожидаемо: в начале строки приглашения появится `(.venv)`.

Если PowerShell выдаёт сообщение о запрете выполнения сценариев, разрешите разово:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

Установите зависимости:

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Установятся пакеты: `psycopg[binary]`, `python-dotenv`, `streamlit` и его зависимости (включая `altair`).

Проверка:

```powershell
python -m pip show streamlit
```

Ожидается строка `Version: 1.52` или новее.

> Дальше во всех шагах подразумевается, что окружение `(.venv)` активировано. Признак — `(.venv)` слева в приглашении. Если терминал перезапускался, активируйте заново: `.\.venv\Scripts\Activate.ps1`.

## 7. Шаг 5. Создать роль и демонстрационную базу

Приложение работает под отдельной ролью `crm_app`, которая владеет базами, но не имеет права создавать новые.

Подключитесь к PostgreSQL как суперпользователь `postgres`:

```powershell
psql -U postgres -h localhost
```

Введите пароль, который задали при установке PostgreSQL. Затем выполните команды (замените `ВашПароль` на свой пароль для роли приложения):

```sql
CREATE ROLE crm_app WITH LOGIN PASSWORD 'ВашПароль';
CREATE DATABASE job_search_crm_demo OWNER crm_app ENCODING 'UTF8';
\q
```

Пояснения:
- `crm_app` — роль приложения; пароль задаётся здесь и повторяется в файле `.env` на следующем шаге.
- `job_search_crm_demo` — **демонстрационная** база с синтетическими данными. Это то, что увидят читатели портфолио.
- Отдельная рабочая база `job_search_crm` для реальных данных создаётся при желании — см. раздел 13.

## 8. Шаг 6. Настроить файл .env

Файл `.env` хранит параметры подключения. Он исключён из Git и не публикуется.

Скопируйте образец:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` в VS Code и заполните реальными значениями. Минимально нужны пять строк:

```
PGHOST=localhost
PGPORT=5432
PGDATABASE=job_search_crm_demo
PGUSER=crm_app
PGPASSWORD=ВашПароль
```

`PGDATABASE=job_search_crm_demo` означает, что **по умолчанию** приложение работает с демонстрационной базой — именно так и задумано для портфолио. Переключение на рабочую базу описано в разделе 13.

## 10. Шаг 8. Загрузить демонстрационные данные

Демо-данные воспроизводимы: фиксированный набор из 96 процессов с псевдослучайными, но одинаковыми при повторной загрузке значениями. Даты считаются относительно «сегодня», поэтому напоминания всегда «живые».

```powershell
python -m db.seed.load_demo_data
```

Скрипт откажется работать не с демонстрационной базой — это защита от случайной очистки рабочей базы.

Ожидаемо в конце:

```
Загружено: процессов 96, записей истории 280, ...
Процессы по текущему статусу:
  ...
```

Если дата загрузки отличается от сегодняшней (например, готовите демо для показа через несколько дней), задайте её явно:

```powershell
python -m db.seed.load_demo_data --today 2026-10-20
```

```powershell

```

В терминале появится:

```

```

Браузер откроется автоматически. Если нет — перейдите по адресу `http://localhost:8501` вручную.

Приложение останавливается сочетанием **Ctrl+C** в терминале.

## 12. Шаг 10. Контрольная проверка

Убедитесь, что всё работает:

1. **Сайдбар** слева: «База данных: job_search_crm_demo».
2. Сверху жёлтая плашка **«Демо-режим: показаны синтетические данные»**.
3. Страница **«Напоминания»** открывается по умолчанию; видны три группы («Сегодня и завтра», «В ближайшие 7 дней», «Нет запланированного этапа») с ненулевыми числами.
4. Страница **«Процессы»**: счётчик «Показано 96 из 96», таблица со всеми процессами, фильтры и поиск работают.
5. **Создайте процесс**: страница «Создать процесс» → заполните обязательные поля → «Сохранить». Произойдёт переход в карточку созданного процесса.
6. В карточке **назначьте этап** (типичный переход — «Техническое собеседование»), **закройте процесс** (итог «Нет ответа»), вернитесь в список — данные сохранились.
7. Страница **«Навыки»** — профиль навыков по направлениям и список пробелов.
8. Страница **«Дашборд»** — три круговые диаграммы воронки и таблицы по источникам, дням между этапами, причинам отказов, навыкам, вилкам.
9. **Ошибки валидации**: попробуйте сохранить процесс с пустой компанией — увидите сообщение об ошибке, данные в форме сохранятся.

Если все девять пунктов прошли — установка завершена.

## 13. Рабочая база (опционально)

Для реальной работы (со своими данными, без демонстрационных) заведите отдельную базу `job_search_crm` и переключайтесь на неё.

Создайте базу от `postgres`:

```sql
CREATE DATABASE job_search_crm OWNER crm_app ENCODING 'UTF8';
```

В новом терминале (с активированным `.venv`) переключитесь на рабочую базу и примените миграции:

```powershell
$env:PGDATABASE = "job_search_crm"
python -m db.migrate
```

Демо-данные в рабочую базу загружать нельзя: загрузчик откажется. Запуск приложения:

```powershell
python -m streamlit run app/main.py
```

Переменная `$env:PGDATABASE` перекрывает значение из `.env` только в **текущем** окне PowerShell. Чтобы вернуться на демо-базу — закройте окно или выполните:

```powershell
Remove-Item Env:PGDATABASE
```

и запустите приложение снова — оно подключится к `job_search_crm_demo` из `.env`.

## 14. Остановка и повторный запуск

**Остановить приложение:** Ctrl+C в терминале, где оно запущено.

### 14.1. Запуск через bat-файлы (простой способ)

В корне проекта лежат два готовых файла:

- `run-demo.bat` — запускает приложение с **демонстрационной** базой (`job_search_crm_demo`);
- `run-work.bat` — с **рабочей** базой (`job_search_crm`).

Оба файла сами активируют `.venv`, задают нужную базу и запускают Streamlit. Двойной клик — и через несколько секунд приложение откроется в браузере.

Чтобы файлы всегда были под рукой:

1. Правый клик по `run-demo.bat` → **Отправить → Рабочий стол (создать ярлык)**.
2. То же для `run-work.bat`.
3. Ярлыкам можно дать понятные имена: «Job Search CRM — демо» и «Job Search CRM — работа». Иконка меняется через свойства ярлыка.

**Остановить приложение:** Ctrl+C в окне, которое открыл bat-файл. Окно не закроется само — в конце появится «Приложение остановлено. Для продолжения нажмите любую клавишу…», что удобно для чтения финальных сообщений.

### 14.2. Запуск из терминала

Если запускаете вручную, в новом окне PowerShell:

```powershell
cd E:\GIT\tw-portfolio\projects\06-job-search-crm
.\.venv\Scripts\Activate.ps1
python -m streamlit run app/main.py
```

По умолчанию приложение подключится к базе, указанной в `.env` (демонстрационной). Чтобы запустить с рабочей:

```powershell
$env:PGDATABASE = "job_search_crm"
python -m streamlit run app/main.py
```

База данных и данные сохраняются между запусками; заново миграции и демо-данные загружать не нужно.

### 14.3. Обновление кода из репозитория

```powershell
git pull
python -m pip install -r requirements.txt
python -m db.migrate
```

Вторая команда — если изменился `requirements.txt`; третья — если появились новые миграции.

### 14.4. Что важно знать про переключение баз

- Переменная `PGDATABASE`, заданная в bat-файле или в терминале, действует только **для текущего запущенного процесса**. Открыли новый терминал или новый bat-файл — база снова берётся из того, что там прописано (в bat-файле — прямо указана; в `.env` — по умолчанию `job_search_crm_demo`).
- Признак демонстрационного режима в приложении — жёлтая плашка «Демо-режим» сверху и «job_search_crm_demo» в подписи под сайдбаром.
- Переключение баз делается перезапуском приложения. Менять базу «на лету» нельзя: соединение устанавливается один раз при старте.

## 16. Возможные проблемы

**`python` не найден.** Python не добавлен в PATH. Переустановите его, отметив галочку **Add python.exe to PATH**, или перезапустите PowerShell.

**`psql` не найден.** Добавьте путь к `bin` PostgreSQL в PATH текущей сессии:

```powershell
$env:Path += ";C:\Program Files\PostgreSQL\18\bin"
```

Замените `18` на вашу версию.

**Не удаётся активировать виртуальное окружение.** Разрешите выполнение сценариев разово:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

**`ModuleNotFoundError: No module named 'db'`.** Запуск выполняется не из корня проекта или окружение `(.venv)` не активировано. Проверьте:

```powershell
pwd
Get-Command python
```

Первая команда должна показать `...\projects\06-job-search-crm`, вторая — путь внутрь `.venv\Scripts\python.exe`.

**Ошибка подключения к базе.** Проверьте три вещи: служба PostgreSQL запущена (в списке служб Windows — `postgresql-x64-18`); в файле `.env` верные `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`; пользователь `crm_app` создан (см. шаг 5).

**Стримлит запустился, но браузер показывает ошибку.** Вероятнее всего, в терминале уже есть трассировка. Прочитайте последние строки — обычно там указано, что именно не так (чаще всего — неверный пароль в `.env`).

**Пустые напоминания, хотя демо-данные загружены.** Дата загрузки демо-данных отличается от сегодняшней. Перезагрузите:

```powershell
python -m db.seed.load_demo_data
```

**Приложение не перезапускается, порт занят.** Закройте прежний терминал, где оно было запущено, или перезагрузите компьютер.
