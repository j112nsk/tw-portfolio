## 1. Назначение документа

История версий продукта Job Search CRM: что добавилось, что изменилось, что исправлено. Отвечает на вопросы «что нового в этой версии» и «когда появилась та или иная возможность».

Этот документ отличается от журналов изменений внутри проектных документов (Vision & Scope, модели данных и др.): там фиксируется история **документа**, здесь — история **продукта**. Изменения только в документации без изменений в продукте сюда не попадают.

## 2. Формат записей

Используется схема, близкая к [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/) и [Semantic Versioning](https://semver.org/lang/ru/):

- **MAJOR** (`X.0.0`) — несовместимые изменения модели данных или публичного поведения.
- **MINOR** (`0.X.0`) — новая функциональность, обратно совместимая.
- **PATCH** (`0.0.X`) — исправления, не меняющие поведение и модель.

Внутри каждой версии — подразделы:

- **Добавлено** — новая функциональность и артефакты.
- **Изменено** — изменения в существующем поведении.
- **Исправлено** — устранённые ошибки.
- **Удалено** — то, что было в предыдущих версиях и больше не поддерживается.

Для первой версии разделы «Изменено» и «Исправлено» не заполняются.

## 3. [1.0.0] — 15.10.2026

Первый публичный релиз MVP: полностью работающее приложение с демонстрационными данными, аналитикой и комплектом документации.

### Добавлено

**Требования и процессы**
- Vision & Scope v2.2 — цели, границы, бизнес-вопросы Q1–Q13, решения D1–D31, риски R1–R16.
- Пользовательские истории v2.1 — 20 историй (Must: 14, Should: 5, Could: 1) с критериями приёмки и трассируемостью.
- AS-IS v1.4 и TO-BE v2.1 — процессы поиска работы без CRM и с CRM; BPMN AS-IS (v1.4); BPMN TO-BE v2.x — в работе.
- Статусная модель v2.1 — 11 статусов, правила SR1–SR14, нетипичные переходы.
- ADR-001 «Учёт только квалифицированных процессов» — обоснование ключевого решения.
- Реестр рисков (R1–R16) — вероятность, влияние, меры.

**Модель данных и база данных**
- Логическая модель v2.1 — сущности, атрибуты, ER-диаграмма Mermaid, правила INV-01–INV-20.
- Физическая модель v2.1 — типы PostgreSQL, ограничения, триггеры, индексы, словарь данных.
- Миграции `001_create_schema.sql`, `002_seed_reference_data.sql`, `003_triggers.sql` — 13 таблиц, 5 триггеров, справочники, индексы.
- Загрузчик демонстрационных данных `db/seed/load_demo_data.py` — воспроизводимый набор из 96 процессов с датами относительно дня загрузки.

**Аналитика**
- SQL-запросы `db/queries/` для ответов на Q1–Q9, Q12, Q13.
- Запрос согласованности `00-integrity-checks.sql` (INV-08, INV-09, INV-10, INV-20).
- Скрипты запуска `db/run_queries.py` и `db/check_integrity.py`.

**Приложение**
- Шесть страниц на Streamlit: «Напоминания», «Процессы», «Создать процесс», «Карточка процесса», «Навыки», «Дашборд».
- Создание процесса (одна форма для обоих инициаторов), смена статуса и закрытие с предупреждениями о нетипичных переходах, правка полей, удаление, тестовые задания, навыки вакансии и профиль по направлениям.
- Напоминания в трёх группах (US-08, US-09) по правилу SR13.
- Дашборд с воронкой и конверсией, источниками и каналами отклика, днями между этапами, срезами, причинами отказов, рейтингом навыков и зарплатными вилками.
- Полупрозрачная раскраска истории: зелёный для этапов, красный для итогов; сортировка по дате записи.

**Документация**
- Руководство администратора — установка и запуск на чистой Windows 10/11.
- Руководство пользователя — по всем Must-историям, в шаблоне «цель → шаги → результат → типичные ошибки».
- FAQ — 30 вопросов по темам «Замысел», «Работа в приложении», «Аналитика», «Данные», «Ограничения», «Окружение».
- Глоссарий — термины предметной области, модели данных, статусов, аналитики и технического стека.
- Стайлгайд — правила письма и оформления для всех текстов проекта.
- README — обзор проекта, стек, структура, способ запуска.

**Запуск**
- `run-demo.bat` и `run-work.bat` — Windows-скрипты запуска приложения с демонстрационной и рабочей базой.

**Тесты**
- `tests/smoke_db.py` — 43 проверки схемы, ограничений и триггеров (в транзакции с откатом).
- `tests/check_queries_demo.py` — 16 проверок аналитических запросов против независимого расчёта на Python.
- `tests/check_app_data.py` — 22 проверки слоя данных приложения.
- `tests/check_app_create.py`, `check_app_stages.py`, `check_app_edit.py`, `check_app_tests.py`, `check_app_skills.py` — проверки записывающих операций.

### Известные ограничения
