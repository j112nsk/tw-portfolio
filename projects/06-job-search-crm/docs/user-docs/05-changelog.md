## 1. Назначение документа

История версий продукта Job Search CRM: что добавилось, что изменилось, что исправлено. Отвечает на вопросы «что нового в этой версии» и «когда появилась та или иная возможность».

Этот документ отличается от журналов изменений внутри проектных документов (Vision & Scope, модели данных и др.): там фиксируется история **документа**, здесь — история **продукта**. Изменения только в документации без изменений в продукте сюда не попадают.

## 2. Формат записей

Используется схема, близкая к [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/) и [Semantic Versioning](https://semver.org/lang/ru/):

- **MAJOR** (`X.0.0`) — несовместимые изменения модели данных или публичного поведения.
- **MINOR** (`0.X.0`) — новая функциональность, обратно совместимая.
- **PATCH** (`0.0.X`) — исправления, не меняющие поведение и модель.

Внутри каждой версии — подразделы:

- **Добавлено** — новая функциональность и артефакты.
- **Изменено** — изменения в существующем поведении.
- **Исправлено** — устранённые ошибки.
- **Удалено** — то, что было в предыдущих версиях и больше не поддерживается.

Для первой версии разделы «Изменено» и «Исправлено» не заполняются.

## 3. [2.0.0] — 21.10.2026

Крупное изменение модели данных: **тестовое задание становится обычным этапом отбора** (ADR-002). Ломающее изменение — статус `APPLIED` и таблица `test_assignments` удалены, миграция конвертирует данные. Добавлены редактирование и удаление записей истории.

### Добавлено

- **Редактирование записи истории** (D33, US-05): в карточке процесса под «Историей этапов» — выбор записи, форма правки (дата этапа, комментарий, статус, причина отказа) и удаление с подтверждением. При смене статуса на не-последней записи текущий статус процесса не сдвигается.
- **Понятное сообщение** при попытке удалить единственную запись истории: «Нельзя удалить единственную запись истории процесса. Если процесс заведён по ошибке, удалите его целиком».

### Изменено

- **Тестовое задание** — обычный необязательный этап отбора (`TEST_ASSIGNMENT`), между HR-интервью и техническим собеседованием; вне воронки (D32, ADR-002). Срок сдачи и результат — текст в комментарии к записи. Несколько тестовых на процесс допускаются (повторная установка этапа).
- **Отдельной сущности `test_assignments` больше нет.** Удалены связанные поля, индексы, проверки и функции: `add_test_assignment`, `update_test_assignment`, `mark_test_submitted`, `delete_test_assignment`, `get_process_tests`. Тестовое задание в списках и SQL-запросах не упоминается.
- **Статус «Отклик» (`APPLIED`) отменён.** Если первым выдано тестовое, первая запись истории — «Тестовое задание» (D32). Начальный статус процесса — любой этап, по умолчанию «HR-интервью».
- **Правила**:
  - SR1: начальный статус — любой этап (было: только HR или APPLIED).
  - SR7: тестовое задание — обычный этап, а не событие.
  - SR9: причина отказа обязательна при наличии любого этапа в истории (было: HR или тестовое отдельно).
  - SR11: максимум `stage_order` при определении «достиг этапа» считается только по этапам с `in_funnel = true` — исправляет ложно-положительный результат для процессов, начавшихся с тестового.
  - SR13: напоминаются только этапы; сроки сдачи тестовых заданий — нет.
  - INV-08 переписан; INV-13 и INV-20 отменены; добавлен INV-21 (правка и удаление записи истории).
- **Длительность процесса**: начало — минимум из даты первого этапа и даты первой записи истории. Процесс с этапом в будущем показывает не 0, а количество дней от момента создания. Конец — сегодня для открытых, дата последней записи — для закрытых.
- **Дашборд «Воронка»**: убрана строка «только тестовое» (отдельного `APPLIED` больше нет).

### Исправлено

- Даты в таблице «История этапов» и в селектбоксе выбора записи не совпадали: `timestamptz` отображался в UTC в `DateColumn`. Теперь в обеих местах — локальная дата (`date` без времени).
- В шапке карточки длительность могла отличаться от списка процессов: `first_recorded_date` не всегда срабатывал без полного перезапуска Streamlit. Обе реализации (SQL и Python) приведены к одной формуле.

### Удалено

- Миграция `005_test_assignment_as_stage.sql` удаляет таблицу `test_assignments` и статус `APPLIED`, конвертирует записи истории (`APPLIED` → `TEST_ASSIGNMENT`).
- Тест `tests/check_app_tests.py` удалён вместе с сущностью.

## 4. [1.0.1] — 16.10.2026

Патч по итогам первых дней использования: 
- подсказки навыков в пустой базе.
- редактирование тестового задания.
- длительность процесса.

### Добавлено

- Миграция `004_seed_typical_skills.sql` — типовой набор из 41 навыка в справочник `skills` (общие, SA/BA, TW). В интерфейсе «Навыки» и «Карточка процесса» при вводе появляется список для выбора сразу после установки, без накопления процессов.
- В списке процесоов и карточке процесса теперь указывается его длительность (в календарных днях).

### Изменено

- Функция подсказок навыков в приложении: если навык ещё не встречался у процессов этого направления, он всё равно предлагается из общего справочника (`get_all_skills`).
- Теперь можно менять комментарий к тестовому заданию (например, указывать резутьтат сдачи).

### Исправлено

- В рабочей базе список навыков был пуст: он строился только по связям «процесс ↔ навык», а на пустой базе связей нет.

## 4. [1.0.0] — 15.10.2026

Первый публичный релиз MVP: полностью работающее приложение с демонстрационными данными, аналитикой и комплектом документации.

### Добавлено

**Требования и процессы**
- Vision & Scope v2.2 — цели, границы, бизнес-вопросы Q1–Q13, решения D1–D31, риски R1–R16.
- Пользовательские истории v2.1 — 20 историй (Must: 14, Should: 5, Could: 1) с критериями приёмки и трассируемостью.
- AS-IS v1.4 и TO-BE v2.1 — процессы поиска работы без CRM и с CRM; BPMN AS-IS (v1.4); BPMN TO-BE v2.x — в работе.
- Статусная модель v2.1 — 11 статусов, правила SR1–SR14, нетипичные переходы.
- ADR-001 «Учёт только квалифицированных процессов» — обоснование ключевого решения.
- Реестр рисков (R1–R16) — вероятность, влияние, меры.

**Модель данных и база данных**
- Логическая модель v2.1 — сущности, атрибуты, ER-диаграмма Mermaid, правила INV-01–INV-20.
- Физическая модель v2.1 — типы PostgreSQL, ограничения, триггеры, индексы, словарь данных.
- Миграции `001_create_schema.sql`, `002_seed_reference_data.sql`, `003_triggers.sql` — 13 таблиц, 5 триггеров, справочники, индексы.
- Загрузчик демонстрационных данных `db/seed/load_demo_data.py` — воспроизводимый набор из 96 процессов с датами относительно дня загрузки.

**Аналитика**
- SQL-запросы `db/queries/` для ответов на Q1–Q9, Q12, Q13.
- Запрос согласованности `00-integrity-checks.sql` (INV-08, INV-09, INV-10, INV-20).
- Скрипты запуска `db/run_queries.py` и `db/check_integrity.py`.

**Приложение**
- Шесть страниц на Streamlit: «Напоминания», «Процессы», «Создать процесс», «Карточка процесса», «Навыки», «Дашборд».
- Создание процесса (одна форма для обоих инициаторов), смена статуса и закрытие с предупреждениями о нетипичных переходах, правка полей, удаление, тестовые задания, навыки вакансии и профиль по направлениям.
- Напоминания в трёх группах (US-08, US-09) по правилу SR13.
- Дашборд с воронкой и конверсией, источниками и каналами отклика, днями между этапами, срезами, причинами отказов, рейтингом навыков и зарплатными вилками.
- Полупрозрачная раскраска истории: зелёный для этапов, красный для итогов; сортировка по дате записи.

**Документация**
- Руководство администратора — установка и запуск на чистой Windows 10/11.
- Руководство пользователя — по всем Must-историям, в шаблоне «цель → шаги → результат → типичные ошибки».
- FAQ — 30 вопросов по темам «Замысел», «Работа в приложении», «Аналитика», «Данные», «Ограничения», «Окружение».
- Глоссарий — термины предметной области, модели данных, статусов, аналитики и технического стека.
- Стайлгайд — правила письма и оформления для всех текстов проекта.
- README — обзор проекта, стек, структура, способ запуска.

**Запуск**
- `run-demo.bat` и `run-work.bat` — Windows-скрипты запуска приложения с демонстрационной и рабочей базой.

**Тесты**
- `tests/smoke_db.py` — 43 проверки схемы, ограничений и триггеров (в транзакции с откатом).
- `tests/check_queries_demo.py` — 16 проверок аналитических запросов против независимого расчёта на Python.
- `tests/check_app_data.py` — 22 проверки слоя данных приложения.
- `tests/check_app_create.py`, `check_app_stages.py`, `check_app_edit.py`, `check_app_tests.py`, `check_app_skills.py` — проверки записывающих операций.

### Известные ограничения

Осознанные границы MVP (полный список — в Vision & Scope, раздел 6.2 «Не входит»); BPMN v2.x — в работе, в релизе только AS-IS v1.4.

## 5. Что дальше

Планы после MVP (порядок условный):

- **BPMN v2.x** — диаграммы TO-BE и этапов отбора под версию 2.x, экспорт SVG.
- **ADR** — отказ от API и скрапинга hh.ru; выбор PostgreSQL; выбор Streamlit; триггерная синхронизация статуса.
- **Тест-кейсы** — формальные тест-кейсы для историй Must.
- **Счётчик откликов** (вариант A2 из ADR-001) — если понадобится оценка отдачи откликов.
- **Автоматическое извлечение навыков** из текста вакансии (после MVP).
