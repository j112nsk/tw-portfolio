# Интеграционные сценарии (Use Cases)

**Актёры:**
- 1С – клиентская ERP
- СБИС – внешний сервис ЭДО
- Шлюз – наш компонент
- Бухгалтер – конечный пользователь

## Сценарий 1. Отправка исходящего документа (УПД) из 1С в ЭДО (СБИС)

Актёр: Бухгалтер в 1С

Предусловие: В 1С сформирован УПД, подписан КЭП, контрагент подключён к СБИС

**Основной поток:**

1. 1С вызывает API шлюза POST /documents/outgoing
2. Шлюз валидирует документ (проверяет обязательные поля, формат)
3. Шлюз преобразует внутренний JSON в формат XML, ожидаемый СБИС
4. Шлюз отправляет документ в СБИС через их API (метод Документ.Отправить)
5. СБИС возвращает идентификатор документа (docId, статус)
6. Шлюз сохраняет статус и возвращает ответ в 1С

**Альтернативные потоки:**

- Ошибка валидации → возврат 400 с описанием

- Недоступность СБИС → шлюз ставит в очередь и повторяет попытки

- Контрагент не найден в СБИС → возврат 422 с предложением пригласить

## Сценарий 2. Приём входящего документа (счёт, запрос) из СБИС в 1С

Актёр: Система (webhook от СБИС)

Предусловие: Шлюз зарегистрирован в СБИС как обработчик событий

**Основной поток:**

1. СБИС отправляет webhook на POST /webhooks/sbis/incoming
2. Шлюз получает XML от СБИС, парсит его
3. Шлюз преобразует в унифицированный JSON и сохраняет во временное хранилище
4. Шлюз вызывает 1С (через HTTP или очередь) с уведомлением о новом документе
5. 1С забирает документ по GET /documents/incoming/{id}

**Альтернативы:** Если 1С не отвечает – повторные попытки с экспоненциальной задержкой

## Сценарий 3. Получение статуса документа (подписан / отклонён)

Актёр: 1С (периодический опрос или webhook)

**Поток:**

1. 1С запрашивает GET /documents/status/{docId}
2. Шлюз проверяет статус в своей БД или запрашивает свежий из СБИС
3. Возвращает статус (sent, delivered, signed, rejected)

## Сценарий 4. Подписание входящего документа (со стороны организации)

Актёр: Бухгалтер в 1С

**Поток:**

1. 1С получает входящий документ (счёт)
2. Бухгалтер подписывает его КЭП в 1С
3. 1С вызывает POST /documents/{docId}/sign с телом (подпись)
4. Шлюз передаёт подпись в СБИС
5. СБИС меняет статус документа на «подписан»
